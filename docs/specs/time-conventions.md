# 时点约定

防止使用未来数据的核心规则，因子、标签、可交易集合、回测，以及将来的实盘交易服务共同遵守。

状态：已定义；因子、标签、可交易集合、回测尚未实现，实现时须补齐下列测试。

## 记号

- `ts`：bar 的**开盘时刻**，UTC 毫秒。所有模块之间唯一的 join 键是 `(ts, symbol)`。
- `freq`：bar 周期，如 1m、1h、1d。
- `t + k`：`t + k·freq`，按日历时间计，不按实际存在的 bar 计数。数据有缺口时两者不同，缺口的处理见下文。（用户 2026-11-05 确认）
- `close(t)`：开盘时刻为 `t` 的那根 bar 的收盘**价**。
- `close_ts(t)`：同一根 bar 的收盘**时刻**，等于 `t + freq`。

## 需求

### 历史回放假设

事件有两种时间：事件时间决定数据归属哪根 bar，可用时间决定决策时能否使用它。Binance Vision 是事后归档的数据，只有事件时间，没有可用时间；官方也可能重新发布某月文件（见 [clickhouse-store.md](clickhouse-store.md) 已知限制），所以无法精确重建当时的信息集。研究统一采用以下假设，并以此为前提解读结论：

- 键为 `t` 的 bar 在 `close_ts(t)` 立即可见，没有传输和处理延迟；资金费率在其规整后的 `ts` 可见。
- 决策和传输延迟只由 `lag ≥ 1` 根 bar 吸收，成交规则见下文"标签滞后成交"。
- 结论只在该假设下成立。模拟盘或实盘有了真实的可用时间后，要用它校准延迟与成交，不能直接沿用回测净值。

这是声明而非算法，没有专门的测试；它约束的是下面各条规则的解读，以及将来接入实时数据时必须另行记录可用时间。

### 因子只用当根 bar 收盘前的数据

键为 `t` 的因子值只能用 `ts ≤ t` 的 bar，在 `close_ts(t)` 时才可知。因子输出沿用 bar 的 `ts`，不另改成收盘时刻。

- 场景：在 `ts = s` 构造一根价格突变的 bar，键 `t < s` 的因子值不变。
- 测试：待因子注册任务实现。

### 标签滞后成交

键为 `t` 的标签为 `close(t + lag + horizon) / close(t + lag) - 1`，`lag ≥ 1`（默认 1）。信号在 `close_ts(t)` 产生，最早按 `close(t + lag)` 成交，不用 `close(t)`。回测用同一定义。

- 场景：`close(s)` 只影响键 `t ∈ [s - lag - horizon, s - lag]` 的标签；键 `t > s - lag` 的标签不变。
- 场景：传入 `lag < 1` 时报错。
- 测试：待标签任务实现。

### 可交易集合只用之前的数据

键为 `t` 的集合只用 `ts < t` 的数据决定，比因子少用一根 bar，即集合在 `t` 开盘前已确定。历史上存在、之后下架的合约必须包含在内。官方文件的末月可能晚于真实停止交易时间，所以按实际成交额筛选，不按注册表的末月筛选。

- 场景：在 `ts = s` 构造一次成交额突变，`universe_at(s)` 不变，只有 `s` 之后的集合可能变化。
- 场景：之后会下架的合约出现在下架前的集合里。
- 测试：待可交易集合任务实现。

### 资金费率按持仓区间左开右闭计费

结算时刻落在 `(close_ts(t + lag), close_ts(t + lag + horizon)]` 内的资金费率计入：开仓时刻那次不算，平仓时刻那次算。标签扣资金费率和回测计费用同一规则，按 `funding_rate.ts`（已规整到秒的结算时刻，不是原始 `calc_time`）计算，不假设固定间隔（币安部分合约为 4h 或 1h）。

- 场景：结算时刻恰好等于开仓时刻的不计入，恰好等于平仓时刻的计入。
- 测试：待成本模型任务实现。存储侧的时刻规整见 [clickhouse-store.md](clickhouse-store.md)。

### 不跨数据缺口计算收益

用户 2026-11-05 确认。官方数据存在整段缺失（例如 2026-10-28 全天没有 K 线）。接入不补值；取数、标签和回测都不得静默补值或把缺口两端连起来算收益。

- 标签：区间 `[t + lag, t + lag + horizon]` 内任意一根 bar 缺失时，键为 `t` 的标签为缺失值。
- 聚合：由 1m 聚合成更粗周期时，输出该周期实际包含的 1m 根数，让使用方据此判断；一根 1m 都没有的周期不输出。
- 场景：在 `ts = s` 处缺一根 bar，区间覆盖 `s` 的标签全部为缺失值，其余标签不受影响。
- 场景：1h 周期内缺 10 分钟，聚合结果的根数为 50。
- 测试：聚合部分已由取数 SDK 实现，见 [data-api.md](data-api.md)；标签部分待标签任务实现。
